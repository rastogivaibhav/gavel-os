# T13 — guarded orphan recovery sweep

Status: IMPLEMENTED_UNVERIFIED until the privileged kernel regression passes. The existing explicit recover command is retained. The new recover-orphans command runs one bounded discovery pass, suitable for an opt-in trusted systemd timer. No service is automatically installed or enabled.

## Security contract

Under A0/A1 and a trusted privileged host, a root-owned bpffs pin identifies a candidate, not proof of ownership. Discover exact generated names and recognized hook suffixes; do not traverse unrelated cgroups or kill merely by directory name. Acquire the existing nonblocking lifecycle lease; contention is a normal busy result, including live supervisors and other recovery operators. Recheck pins after acquiring the lease. If normal cleanup completed, report gone. Otherwise validate the trusted cgroup path and require all four existing BPF links to identify its kernel cgroup ID and the expected connect4/connect6/sendmsg4/sendmsg6 attach types. The cgroup v2 inode is used as the kernel cgroup ID on supported Linux amd64/arm64. Mismatch, missing cgroup, partial pins, or unexpected metadata is an error; retain the existing state and request explicit operator review. Do not remove an unknown pin. Verified candidates use the existing lease-held kill, confirm populated 0, unpin and remove sequence. A failure to prove emptiness leaves links pinned. Recovery is destructive to the orphan workload, not a restart or reattachment service.

Scope: one trusted cgroup parent per host-wide pin/lease namespace; configure the same GAVEL_CGROUP_PATH as guarded launches. Host must reserve GavelOS names, avoid out-of-band changes, use stable shared /run and bpffs mounts, and stop older guarded supervisors before upgrade. A malicious host root, concurrent noncooperating privileged writer, older unleased supervisors, missing or partially rolled-back pins, empty cgroups without pins, cross-parent migration and mount namespace changes are excluded from automatic recovery. Ambiguous partial state is deliberately left for the operator; a failed sweep is not proof of quarantine. The command has no policy control-plane dependency. Legacy PID mode is not protected by this feature.

## Optional scheduling

Only install after reviewing the tested release and deployment assumptions. Use a root-owned installed executable at /usr/local/bin/gavel-enforcer, mounted bpffs and cgroup v2. Configure /etc/gavel/recovery.env (root-owned 0600) with the same explicit GAVEL_CGROUP_PATH as the guarded supervisor. Do not include machine keys or unrelated secrets. On an authorized test host, run the command manually and inspect its exit status and journal before enabling the service. Example deployment units are deploy/systemd/gavel-orphan-recovery.service and .timer. They run once per activation, repeat approximately 30 seconds after completion, and do not restart payloads. Timer and service may be disabled by the trusted operator. Monitor nonzero service results and alert; do not assume all candidates were recovered. Automatic systemd scheduling, boot ordering and long-running operational behavior are not covered by this kernel regression.

## Regression

TestKernelGuardedOrphanSweep repeats the existing real supervisor SIGKILL scenario, tests a sweep during the live lease (workload and four links retained), verifies post-crash denied IPv4/IPv6 TCP and UDP on the surviving descendant, checks a competing lease, verifies rejection of a real same-name cgroup under the wrong parent, runs the sweep without providing a workload name, verifies the unrelated unpinned cgroup remains and all orphan pins/cgroup are removed, then repeats the sweep. Existing manual recovery test remains separate. Full inventory: 20 standalone kernel assertions. Partial pin/missing cgroup fault injection and independent reproduction remain future tests. No host-root resistance or formal T13 closure claim.
