# T13 — guarded orphan recovery sweep

Status: IMPLEMENTED_UNVERIFIED until the privileged kernel regression passes. The existing explicit recover command is retained. The new recover-orphans command runs one bounded discovery pass, suitable for an opt-in trusted systemd timer. No service is automatically installed or enabled.

## Security contract

Under A0/A1 and a trusted privileged host, a root-owned bpffs pin identifies a candidate, not proof of ownership. Discover exact generated names and recognized hook suffixes; do not traverse unrelated cgroups or kill merely by directory name. Acquire the existing nonblocking lifecycle lease; contention is a normal busy result, including live supervisors and other recovery operators. Recheck pins after acquiring the lease. If normal cleanup completed, report gone. Otherwise validate the trusted cgroup path and require every remaining BPF link to identify its kernel cgroup ID and expected attach type. At least one matching link is required for initial attribution. The cgroup v2 inode is used as the kernel cgroup ID on supported Linux amd64/arm64. Mismatch, missing cgroup with remaining pins, or unexpected metadata is an error; retain existing state and request explicit operator review. Partial but consistently attributed orphan state is terminated with a critical warning that protection was already incomplete. Do not remove an unknown pin. Verified candidates use the existing lease-held kill, confirm populated 0, unpin and remove sequence. A failure to prove emptiness leaves links pinned. Recovery is destructive to the orphan workload, not a restart or reattachment service.

Scope: one trusted cgroup parent per host-wide pin/lease namespace; configure the same GAVEL_CGROUP_PATH as guarded launches. Host must reserve GavelOS names, avoid out-of-band changes, use stable shared /run and bpffs mounts, and stop older guarded supervisors before upgrade. A malicious host root, concurrent noncooperating privileged writer, older unleased supervisors, unattributed zero-pin cgroups, empty cgroups without pins or a receipt, cross-parent migration and mount namespace changes are excluded from automatic recovery. Ambiguous partial state is deliberately left for the operator; a failed sweep is not proof of quarantine. The command has no policy control-plane dependency. Legacy PID mode is not protected by this feature.

## Optional scheduling

Only install after reviewing the tested release and deployment assumptions. Use a root-owned installed executable at /usr/local/bin/gavel-enforcer, mounted bpffs and cgroup v2. Configure /etc/gavel/recovery.env (root-owned 0600) with the same explicit GAVEL_CGROUP_PATH as the guarded supervisor. Do not include machine keys or unrelated secrets. On an authorized test host, run the command manually and inspect its exit status and journal before enabling the service. Example deployment units are deploy/systemd/gavel-orphan-recovery.service and .timer. They run once per activation, repeat approximately 30 seconds after completion, and do not restart payloads. Timer and service may be disabled by the trusted operator. Monitor nonzero service results and alert; do not assume all candidates were recovered. Automatic systemd scheduling, boot ordering and long-running operational behavior are not covered by this kernel regression.

## Regression

TestKernelGuardedOrphanSweep repeats the existing real supervisor SIGKILL scenario, tests a sweep during the live lease (workload and four links retained), verifies post-crash denied IPv4/IPv6 TCP and UDP on the surviving descendant, checks a competing lease, verifies rejection of a real same-name cgroup under the wrong parent, runs the sweep without providing a workload name, verifies the unrelated unpinned cgroup remains and all orphan pins/cgroup are removed, then repeats the sweep. Existing manual recovery test remains separate. Full inventory: 20 standalone kernel assertions. Independent reproduction and boot-time validation remain future tests. No host-root resistance or formal T13 closure claim.

## Recovery fault tolerance — follow-on

Status IMPLEMENTED_UNVERIFIED. Both manual and sweep recovery share a lease-held path. After matching at least one real pin (and validating every remaining pin), kill the target, observe populated 0 and atomically publish a mode-0600 root-owned receipt under /run/gavel-guarded-lifecycle containing version, parent, name, device and inode. Sync receipt and directory before unpinning. A partial attributed orphan is stopped, not repaired or resumed; missing coverage before recovery cannot be retroactively claimed. The receipt permits discovery and cleanup even after the last pin was removed. Retry checks exact cgroup identity, remaining hook identities and current emptiness; a repopulated target is refused and remaining pins retained. If both cgroup and pins are absent, remove the completed receipt. No pins and no receipt means no authorization to recover a present cgroup. New launch refuses reuse of unresolved receipt name. Stable trusted /run, cgroup and bpffs mounts and cooperating privileged operators required. This boot-local receipt is not an authenticated attestation or power-loss journal. Fault injection uses actual kernel objects and a live unprivileged fixture but does not SIGKILL the recovery process itself at each instruction. Normal supervisor cleanup is not journalled by this slice; all-pin loss before a receipt, cgroup disappearance with surviving pins, and noncooperating root changes remain operator incidents. Do not assert quarantine after an error. Full current regression inventory 21.
