P0.1 deliberately uses close_range(CLOEXEC) in the dedicated trusted supervisor, requires atomic CLOEXEC for any concurrent trusted opens, and only preserves the sealed public filter FD. stdin becomes /dev/null; stdout/stderr must already be write-only pipes or /dev/null. Operators must launch with trusted output sinks (no direct terminal/file/socket redirection). Existing output pipes remain an authorized communication channel, not a general IPC guarantee. This does not prohibit later descriptor transfer, procfs reopening, same-UID helper access, or all inherited resources in non-guarded PID mode. Requires Linux >=5.11; fail closed on unsupported close_range. No tests on live user hosts.

## P0.2 strict Unix socket boundary

Guarded seccomp refuses all newly created externally addressable AF_UNIX sockets (pathname and abstract), while allowing AF_UNIX SOCK_STREAM socketpair for private same-domain communication. Datagram/seqpacket pairs and pidfd_getfd are denied. This intentionally breaks applications requiring D-Bus, Docker sockets, local Unix agents or other Unix services; there is no compatibility bypass. The change does not inspect ancillary data on approved private pairs: transfers of descriptors already held within the protected domain are allowed. Tests must show actual external synthetic descriptor receipt without the guard, kernel denial with the guard, no external server connections, allowed private stream communication and fork/exec inheritance. Same-UID /proc reopening, other IPC mechanisms, allowed TCP helper services, output-pipe consumers and privileged brokers remain separate gates. Requires P0.1's trusted launch descriptor boundary. Independent review pending.

## P0.3 native and mapped destination blocklists

Both connect6 and sendmsg6 check the IPv4 map for exact ::ffff:0:0/96 addresses in addition to the IPv6 map. Native IPv6 stays on its own exact-key policy. Guarded tests explicitly create AF_INET6 dual-stack sockets rather than relying on Go's family selection. Test native IPv4, native IPv6, mapped IPv4 TCP, connected UDP write, explicit sendto/sendmsg on both connected and unconnected UDP, positive unguarded receiver controls and guarded descendants. This is destination blocklist enforcement, not default deny, semantic API policy, proxy parity, UDP-Lite or exhaustive protocol coverage. Existing connected descriptors from outside the guard, trusted helpers, and dynamic policy updates/revocation are not covered. CI pending; no independent review.

## P0.4 exclusive workload identity (first slice)

Guarded startup obtains a root-only, nonblocking per-UID flock under /run/gavel-guarded-uids and scans the host-visible procfs task credential records (real/effective/saved/filesystem UID) before allowing the workload to launch. Any observed matching UID, inaccessible credential record other than a vanished task, or invalid procfs/lease directory is a launch error. The lease remains held through cleanup; an orphan visible after supervisor SIGKILL is detected by the next scan. Never unlink lock files (inode replacement would permit simultaneous holders). process_vm_readv now explicitly denied alongside process_vm_writev, ptrace and pidfd_getfd. This is conservative admission control, not a kernel-enforced UID reservation: trusted host must dedicate the UID to this workload, prohibit other services/login or external launch using it, and expose the full host PID namespace/procfs. A scan cannot atomically prove absence under arbitrary concurrent external process creation or PID churn. Existing output consumers, permitted network helpers, shared GID permissions, filesystem aliases and non-socket IPC are not addressed. Dedicated UID must not be a shared account. CI pending; independent validation pending.

## P0.4 System V IPC and POSIX message queues

Strict guarded seccomp denies the native amd64/arm64 System V shared memory, message queue and semaphore syscall families and POSIX message queue syscall family. There is no opt-out or compatibility fallback. Tests exercise real synthetic shared memory, queue and semaphore objects with an unguarded unprivileged positive control, guarded parent and descendant negative controls, and host-side unchanged object state. Anonymous private memory and ordinary pipes remain usable. POSIX shared memory via files (including /dev/shm), file-backed mmap, named FIFOs, shared filesystem/GID permissions, procfs exposure, and authorized TCP services are distinct surfaces; this does not close them. Landlock is optional and does not replace helper authorization. Existing UID admission is conditional on exclusive host assignment and full procfs visibility. No independent review. PRs #18/#19 merged at 79e8f960ed83da5987b02635ffc7eaa34b5e9792; tree identical to tested #19.

## P0.4 isolated filesystem profile (next slice, unverified)

Select GAVEL_AGENT_FS_PROFILE=isolated to require an explicit Landlock filesystem policy. Missing/invalid policy, unknown profile, unsupported ABI or rules for host IPC/pseudo-filesystem roots (/dev/shm, /dev/mqueue, /proc, /sys, /run) or their ancestors are launch errors. Both supplied and resolved paths are checked. The profile is intentionally opt-in for legacy guarded deployments; when selected there is no downgrade. Kernel tests must demonstrate denied access to a real synthetic /dev/shm file and an external named FIFO outside the allowlist, unguarded positive controls, unchanged external state, allowed private file mmap and descendant inheritance. The operator must provide a private nonshared workspace, trusted path/mount layout and prevent outside processes from introducing aliases or IPC objects into authorized paths. Bind mounts/hardlink aliases, pre-opened FDs, FIFOs inside allowed trees, all device ioctls, metadata and permitted network helpers are not comprehensively mediated. This is not general IPC isolation. PR #20 remains a prerequisite; run 45908105713 was queued at this change. No independent review.

## P0.4 default-deny TCP service profile (unverified)

GAVEL_AGENT_NET_PROFILE=tcp-services selects an explicit local-only TCP endpoint allowlist from GAVEL_AGENT_TCP_ALLOW (JSON array of literal IP:port strings, [] means no outbound endpoints). Missing/malformed policy, unknown profile, control-plane mode, blocklist/redirect conflicts or map/attach errors refuse launch. All four hooks remain mandatory; connect4/connect6 use a canonical IPv6-shaped address plus network-order port key (IPv4 mapped), UDP hooks deny. Seccomp restricts new IP sockets to stream TCP, denies listen/accept and MSG_FASTOPEN sends. Private stream pairs remain. This is an opt-in destination-level authorization slice, not application-layer authorization: allowed endpoints must be trusted, no semantic or DNS identity assurance, proxy/tunnel or external network broker authorization is not supplied. No packet-level or exhaustive socket path claim; independent reproduction required. PR #20/#21 prerequisites still queued for privileged CI at implementation time.

## P0.5 immutable active policy and pin directory integrity

PRs #20/#21/#22 passed all six jobs in runs 45908105713, 45908274836 and 45908961917 respectively; remain unmerged. Guarded policy maps are BPF_F_RDONLY_PROG at creation and frozen via BPF_MAP_FREEZE after population and before attachment, including unused policy maps. Any freeze failure aborts before attach/payload. Guarded maps are per-launch immutable snapshots; policy change requires trusted stop and new launch. Legacy monitored-PID behavior unchanged. Pin root now validates trusted bpffs ancestry. Tests require successful pre-freeze changes and denied post-freeze update/delete using host handles, preserved map values, and guarded parent/descendant denied unlink or rename of their own links, denied recovery, positive/negative network controls and normal cleanup. No claim of root-resistant link integrity, signed configuration or audit integrity. New CI pending. Independent review still required.

## P0.5 lifecycle serialization and recovery integrity

PR #23 [run 45909974360](https://github.com/rastogivaibhav/gavel-os/actions/runs/45909974360) passed all six jobs, including frozen map updates/deletes, pin tamper denial and continued network enforcement. PRs #20–#23 remain unmerged. This slice serializes launch, execution, cleanup and independent recovery using a root-owned per-cgroup flock in /run/gavel-guarded-lifecycle. The lease is close-on-exec, never passed to the workload, and held until after deferred cleanup. Recovery refuses a live supervisor or concurrent recovery rather than detaching active protection. After SIGKILL, the lease is released by the kernel and the independent recovery path still kills the full cgroup and proves emptiness before unpinning. Lock files are not unlinked during service lifetime; host operators may clean them only offline after all supervisors/recovery processes have exited. Trusted host must provide a shared stable /run mount and upgrade only with no live older guarded supervisors. A failed admission lease may leave an empty cgroup requiring trusted cleanup. This is cooperating trusted process coordination, not resistance to malicious root or direct out-of-band unpinning. Kernel tests extended; CI and independent reproduction pending. Signed policy provenance, complete mediation, semantic authorization and independent evidence remain open. Do not disable engineering schedule.

## Consolidated master evidence and versioned policy provenance

PRs #20–#24 merged at 451c314907fea74cd3b9e40684ad1bc1028692fa; tree identical to tested #24 (run 45910987476, all six jobs, 16 kernel assertion steps). All five P0 areas have scoped tested implementations on master; no independent reproduction. Historical entries above describe the status at each slice, not current branch state. This change adds schema gavel-guarded-policy-v1: a canonical SHA-256 digest of resolved network policy (deduplicated/sorted exact keys, proxy configuration, profile), workload UID/GID, architecture, policy source, compiled Landlock arguments and the actual sealed seccomp file bytes. Optional GAVEL_AGENT_EXPECTED_POLICY_DIGEST=sha256:<64 lowercase hex> requires exact match before cgroup creation or attach; malformed or mismatched values refuse startup. The trusted supervisor emits a snapshot digest associated with its cgroup after all maps are frozen and links pinned, before payload start. This receipt does not attest successful payload execution. No machine key, payload argv or raw policy contents are logged. This is configuration provenance, not a signed policy, authenticated audit receipt, program-bytecode measurement, file identity attestation, secure boot, or protection against trusted root. Host must supply and protect the expected digest and logs. The digest schema must change if its semantics change. Tests and independent reproduction pending. Original issues #2–#8 remain open; see current acceptance matrix and explicit exclusions. Schedule remains active.
